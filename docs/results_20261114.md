## 1. PSS 分流（sic4，SSB IP 1.3）

全雙工時每片板子的接收端會同步到自己發射的 PSS（e16 的 rx_self 約 9～14 萬），佔掉接收時槽。

- SSB IP 1.3（`fpga/ip_mod/SSB_v3_5G_IP_v1_3`）：加入 PSS1 相關器，執行時用 SSB AXI-lite R2（0xB0009008）選擇：bit0＝偵測 PSS1，bit1＝關閉區分。
- 區分：選中的 PSS 相關值必須大於另一個才算偵測。Codex 只看 PSS1 的版本在只有 PSS0 的輸入上會誤觸發；XSim（`fpga/sim/pss_disc`，Codex 的 PSS0-only 擷取資料）無區分 4 次誤觸發、有區分 0 次；混合輸入時只在 PSS1 burst 後觸發。
- 板 1 發射 PSS1 的 SSB（`slotFR2_CH1_SSB_TX1_PSS1.txt`，與原檔只差 PSS 的 64 個值）並偵測 PSS0；板 0 發射 PSS0 並偵測 PSS1。`bidi_run.sh` 的 `PSS=split`（現在是預設）。

## 2. 發射 trigger 卡死（sic5，stream_manager 1.1）

e18／e19：板 1 的 `triggerTX` 突然再也收不到 ACK；控制服務的紀錄在那一刻之後收不到任何指令，只能重載 bit。

原因在 `stream_manager` 的 `packet_fragmentation.v`：
- trigger 上升緣只在 `WAIT_TRIGGER` 狀態取樣：下一個 `triggerTX` 若在前一個 burst 還在 SEND/IDLE 時到達（資料晚一點送到 FPGA 時就會），就被漏掉；
- `transfer_size` 是即時讀的：送到一半被下一個 trigger 改寫，正在送的 burst 長度跟著變。

結果是有資料留在 TX FIFO，背壓堵住和控制共用的網路輸入。XSim（`fpga/sim/stream_manager`）重現：原版 20 beat 只送出 12、8 個卡住，之後每個 burst 都錯位；新版 20/20 依序送出。

修正（`fpga/ip_mod/stream_manager_1_1`）：參數 `LATCH_TRIGGER=1`（只用在 TX 實例）時，送到一半到達的 trigger 連同當時的 `transfer_size` 記下來，目前的 burst 送完後立刻開始；正在送的 burst 使用 trigger 當下鎖存的長度。RX 實例不變。

這個修正與調變方式無關；16/64/256QAM 版本與之後的中繼節點（同時收與轉發）用同一個 stream_manager，也應該套用。
