# 2026-11-13 雙向全雙工測試紀錄

兩片 RFSoC4x2（板 0＝PC 端、板 1＝Mac 端），天線相距約 10 cm，兩板都載 `helix_nlsg_sic3.bit`。每次執行兩邊同時發送自己的攝影機 1080p H.264（`-c copy`），收到的位元組對對方原始檔逐位元組比對（`board/sic/bidi/holes.py`）。

## 依序改了什麼、每一步的效果

| 執行 | 設定 | 板 0 收板 1 | 板 1 收板 0 | 備註 |
|---|---|---|---|---|
| b1 | IFG 200000、間隔 196 µs、每 TB 3 次（同一 burst 內）、AGC 800 | 99.88 % | 78.5 % | 兩邊啟動差 13 秒（板 1 開頭 14 % 沒收到）；之後另缺約 7 % |
| b4 | 同上，兩邊同時 `go` | — | 中途停止（約 59 %） | 板 1 接收在對方還在送時完全停止 |
| b5 | IFG 250000、間隔 240 µs | 99.61 % | 96.47 % | 沒有停止 |
| b6～b8 | 板 1 只收不發（對照） | — | 單包壞率 24～28 % | 板 1 方向的鏈路本身就差，與 SIC 無關；改 RX 頻率 +15 kHz、AGC 關閉都沒改善 |
| b9 | 每 TB 5 次、板 1 AGC 關 | — | 停止 | 收到 63958 包（≈2×32768 少 1578）時停住：主機端掉了封包，Stream Manager 數完一批就不再送 |
| b10 | ＋接收重新 trigger（0.5 s 沒封包） | 99.26 % | 98.25 % | 不再停止 |
| b11 | 每 TB 6 次（同一 burst 內） | 98.9 % | 95.7 % | 重送次數增加反而變差：發射佔空比變高、兩邊重疊變多，掉的是整個 burst |
| b12 | 每 TB 4 次，**分散在 4 個 burst** | 99.76 %（開頭之後 0 缺洞） | 98.30 % | |
| b13 | 每 TB 6 次，分散在 6 個 burst | 99.50 % | 99.91 % | |
| b14 | 同 b13，110 秒 | 99.43 % | 96.07 % | 板 1 損失集中在檔案 80～81 % 處 |
| p1 | 同 b13，用 `tools/run_pair.sh` | 99.77 % | 99.94 % | 驗證 repo 內的腳本 |

所有執行「混入自己的資料」都是 0（節點編號過濾）。SIC 校準預測消除量每次 5～15 dB，ADC 峰值 500～1200。

## 對照：11/12 單向全雙工（只有一邊發攝影機）

PC 端板子同頻全功率發射＋SIC、Mac 端只發攝影機：收到 99.935 %（fdv2）。雙向時 b13／p1 兩個方向都在 99.5 % 以上。
